# RootWarden v1.21.1 — Patch UX bashrc

Mini bump apres v1.21.0 pour amelioration UX du module Bashrc. Pas de patch securite.

## Changements

### 1. Multi-deploy bashrc

Le dropdown mono-serveur du module Bashrc remplace par une **checklist multi-select**.

- Mode mono-serveur (1 coche) : comportement legacy preserve (selection fine des users + Apercu/Deployer/Dry-run).
- Mode multi-serveurs (>=2 coches) : bandeau info + boutons **"Deployer multi" / "Dry-run multi"** violets, qui iterent sur N machines et deploient sur tous les non-system users de chaque.

UI ameliorations :
- Layout vertical : tableau 1 ligne/serveur (nom, IP, env, dernier deploy).
- Header `<thead>` sticky au scroll pour les gros parcs.
- Boutons "Tout / Aucun" pour cocher en masse.
- Compteur live des serveurs selectionnes.
- Results aggregator avec `<details>` collapsibles par serveur.

### 2. Colonne "Dernier deploiement"

Nouvelle colonne extraite de `user_logs` (action `LIKE '[bashrc] deploy%machine_id=X%'`, exclut `dry_run=True`).

Code couleur par anciennete :
- Vert (<30j) : recent, OK
- Jaune (30-90j) : a rejouer si template a evolue
- Rouge (>90j) : trop vieux, redeploiement recommande
- Italique gris : jamais deploye

Dates formatees en fuseau navigateur via `fmtLocalDate()` (UTC -> local).

### 3. Fix collateral CSP (regression de la v1.21.0)

Le patch A05-NEW-04 de la v1.21.0 ajoutait un nonce dans `script-src` ET gardait `'unsafe-inline'`. Probleme : **CSP3 ignore automatiquement `'unsafe-inline'` quand un nonce est declare**. Resultat : tous les `<script>inline</script>` du repo etaient bloques silencieusement par le navigateur, dont le bridge i18n du module Bashrc.

Symptome visible : les cles i18n s'affichaient en raw (`bashrc.multi_deploy_info`) au lieu des traductions. Aussi : tabs, htmx, etc.

**Fix** : rollback du nonce dans `csp_header_value()`. Retour a `'unsafe-inline'` pure (comme avant le patch). La CSP garde les autres directives (frame-ancestors, base-uri, form-action, etc.).

Procedure de reactivation documentee dans `www/includes/csp_nonce.php` : migrer tous les `<script>inline</script>` du repo avec `nonce="<?= csp_nonce() ?>"`, puis retirer `'unsafe-inline'`.

### 4. Convention Tailwind purged respectee

Cf. [[feedback-tailwind-purged-classes]].

Classes Tailwind utilisees verifiees presentes dans le build PurgeCSS :
- `dark:bg-gray-900/30` (non compile) -> `dark:bg-gray-800/50` (compile)
- `bg-purple-700`, `bg-purple-300/400`, `hover:bg-purple-700` (non compiles) -> inline styles hex (`#7c3aed` violet 600, `#6d28d9` violet 700, `#ede9fe` violet 50) avec `onmouseover/out` (technique deja utilisee pour le bouton reboot rouge en v1.20).

### 5. i18n FR/EN

12 nouvelles cles parite :
- `bashrc.servers`, `bashrc.all`, `bashrc.none`
- `bashrc.btn_multi_deploy`, `bashrc.btn_multi_dryrun`
- `bashrc.multi_deploy_info`, `bashrc.multi_users_auto`
- `bashrc.multi_pick_2_min`, `bashrc.multi_in_progress`
- `bashrc.confirm_multi_deploy`, `bashrc.confirm_multi_dry`
- `bashrc.col_name`, `bashrc.col_ip`, `bashrc.col_env`, `bashrc.col_last_deploy`
- `bashrc.never_deployed`
