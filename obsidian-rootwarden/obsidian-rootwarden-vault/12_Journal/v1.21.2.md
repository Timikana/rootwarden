# RootWarden v1.21.2 — Patch UX cles API

Mini bump apres v1.21.1 : refonte du module gestion des cles API + rotation guidee. Pas de patch securite.

## Changements

### 1. Formulaire de creation refondu

Avant : un seul champ nom + un textarea scope (regex 1 par ligne). Non friendly pour des admins non-devs.

Apres :
- **8 modeles rapides** (chips cliquables) qui pre-remplissent nom + scope :
  - Tout (legacy) → `php-proxy-YYYY-MM-DD`, scope vide = ALL
  - Lecture seule → `readonly-dash`, regex GET-only
  - Scan CVE → `cve-scanner`, regex `^/cve_`
  - Deploiement SSH → `deploy-bot`, regex `^/deploy`, `^/preflight_check$`, `^/platform_key$`...
  - Maj APT → `apt-runner`, regex `^/apt_`, `^/update`...
  - Audit SSH → `ssh-auditor`, regex `^/ssh-audit/`
  - Monitoring → `monitor-probe`, regex liste/status
  - Vider → reset le formulaire
- **Checklist de 15 modules** : cocher genere automatiquement le textarea de scope (union des regex coches).
- **Textarea avance** sous `<details>` pour edition manuelle (mode pro).
- Auto-suggestion du nom : `{preset_hint}-YYYY-MM-DD` si vide.

### 2. Bouton "Cles API" dans la toolbar admin

Avant : `/adm/api_keys.php` accessible uniquement par URL directe. Avec ce patch, bouton visible entre **SSH Keypair** et **Backups** dans `admin_page.php`.

i18n FR/EN :
- `admin.btn_api_keys` : "Cles API" / "API Keys"
- `admin.tip_api_keys` : "Gerer les cles API segmentees avec scope par regex de route"

### 3. Bouton "↻ Renouveler" sur cles revoquees

Avant : pour rotater, l'admin devait recreer manuellement avec le bon scope. Risque d'oubli ou d'erreur.

Apres : bouton bleu **↻ Renouveler** sur chaque ligne revoquee (sauf `auto_generated`).
- Recree avec meme `scope_json` + meme `consumer_hint`
- Nouveau nom : `{base}-rYYYYMMDD-HHMMSS` (strip d'un suffixe `-rXXX` precedent pour eviter `xxx-r20260520-r20260521`)
- Garde-fous : refuse si cle encore active (anti-doublon), refuse `auto_generated`, valide nom contre `^[a-zA-Z0-9_-]{3,100}$`
- Audit log : `Renouvellement cle API 'old' -> 'new' prefix=...`

### 4. Champ `consumer_hint` (option A+B)

Question : "si je renouvelle, est-ce que ça deploie automatiquement ?"
Reponse : **NON**, la plateforme ne touche pas aux secrets de deploiement (`srv-docker.env`, secrets k8s, vault). Volontaire (zero-trust).

Mais sans rappel, l'admin oublie ou la cle est utilisee → tout casse silencieusement.

Solution :
- Migration `047_api_keys_consumer_hint.sql` : colonne VARCHAR(200) nullable, idempotente
- Champ form "Ou sera utilisee cette cle ?" optionnel, max 200 chars, **pas de credential stocke**, juste un memo
- Recopie automatique au renouvellement
- Bandeau vert post-creation affiche un rappel personnalise :
  - Avec hint : "📋 Coller dans : `srv-docker.env:API_KEY`"
  - Sans hint : checklist generique (srv-docker.env, CI/CD, k8s secrets, ansible-vault) + tip "renseigne le champ a la prochaine creation"
- Colonne "Consommateur" dans la table (tronquee a 32 chars, `title=` full au hover)

### 5. Banner anciennete + warning maj.sh

Bonne pratique securite : rotater periodiquement les credentials a long terme (90j warning, 180j alerte). Une cle compromise reste a risque meme utilisee tous les jours → source = `created_at`, pas `last_used_at`.

**UI** : banner en haut de `/adm/api_keys.php` si cles actives non-auto-generees > seuils.
- Jaune (90-179j) : ⏰ "Pense a rotater : N cle(s) actives depuis plus de 90 jours"
- Rouge (>=180j) : 🔁 "Rotation recommandee : N cle(s) actives depuis plus de 180 jours"
- Liste : age en jours (chip color-codee), nom, consumer_hint

**CLI** : etape 6 de `maj.sh` interroge la DB en silence et affiche un warning en fin de pipeline.
- Failsafe : skip silencieux si table/colonne absente (boot initial avant migration 047)
- Lit `MYSQL_DATABASE` + `MYSQL_ROOT_PASSWORD` depuis `srv-docker.env`
- Output exemple : `[maj] 2 cle(s) API actives entre 90 et 180 jours - pense a les rotater. Voir /adm/api_keys.php.`

```bash
cd /opt/rootwarden
./maj.sh
```

- Migration 047 appliquee par `db_migrate.py`

- Etape 6 affiche le warning anciennete si applicable
