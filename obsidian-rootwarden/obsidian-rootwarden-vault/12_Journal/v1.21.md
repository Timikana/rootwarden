## Patches CRITIQUES

### A01-01 / A04-01 — Backend ne fait plus confiance aux headers HTTP

Avant : `get_current_user()` lisait `X-User-Role` / `X-User-Permissions` brut. Si l'API_KEY fuit, un attaquant peut forger `role=3` -> escalation superadmin.

Apres : `get_current_user()` charge role + active + permissions depuis la table `users` / `permissions`. Headers ignores. Cache par requete via `flask.g`. Failsafe `(0,0)` si user inactif/DB down.

### A02-01 — AES-256-GCM au lieu de CBC

CBC sans MAC = malleable (bit-flipping). Un attaquant avec acces ecriture BDD pouvait alterer les SSH passwords / TOTP secrets / root_password sans detection.

Maintenant : nouvelles ecritures en `gcm:` (AEAD, tag verifie). Lecture `aes:` legacy preservee pour migration progressive.

### A08-01 — `audit_seal.php` ne reecrit plus les lignes scellees

Avant : si une ligne deja scellee ne matchait pas son hash recalcule, `audit_seal` reecrivait `prev_hash` + `self_hash`. Un superadmin compromis annulait la tamper-evidence en 1 clic.

Apres : `WHERE id = ? AND self_hash IS NULL` garde SQL. Detection des desyncs -> log hors-bande + arret du sealing.

### A04-03 — `shlex.quote` sur arguments shell

`reg_pwd` Wazuh interpolait directement dans `WAZUH_REGISTRATION_PASSWORD='$reg_pwd'`. Un password contenant `'` donnait une RCE root distante sur N serveurs.

Maintenant : `shlex.quote()` partout (Wazuh install + Graylog test_forward + bashrc restore).

## Patches HIGH (selection)

- **A01-02** `/server_status` : machine_id obligatoire + `@require_machine_access` (anti LAN scan)
- **A01-03** `delete_user` : `targetRole < currentRole` strict (admin ne peut pas delete pair)
- **A01-04** `update_server_access` : refus self-grant pour non-superadmin
- **A02-02** decrypt strict : `errors='ignore'` supprime, PKCS7 valide, UTF-8 strict. Plus de retour silencieux de garbage
- **A02-04** TOTP fail-closed : `RuntimeException` si SECRET_KEY absente (plus de plaintext fallback)
- **A04-02** `api_proxy.php` whitelist explicite ~46 prefixes (plus de IDOR sur nouveaux blueprints)
- **A06-01** `requirements.txt` pinne en `==`
- **A07-01** rate-limit 2FA chainage `if/elseif/else` exclusif
- **A07-02** fallback API_KEY opt-in via `API_KEY_BOOTSTRAP=1`
- **A08-02** audit log HMAC-SHA256 + cle dediee `AUDIT_HMAC_KEY` (auto-generee)
- **A09-04** scrubber logs centralise `backend/log_scrub.py` applique sur TOUS les handlers
- **A10-01** blocklist IP machine : loopback, 169.254.x (AWS metadata), 0/8, ::1, fe80:
- **A10-02** SSRF guard sur URLs externes : `_url_is_safe_external()` cote Python

## Patches vague 2 (re-audit)

Le re-audit a revele 3 patches incomplets :

- **A02-NEW-03** : `AUDIT_HMAC_KEY` etait absent de `srv-docker.env.example` -> 100% des installs utilisaient `SECRET_KEY` en fallback (separation nulle). Ajout + warning runtime + **auto-gen `openssl rand -hex 32` dans `env-merge.sh`**.
- **A10-SSRF-N1** : `NVDClient` et `scan_component_via_nvd` ne passaient PAS par `_url_is_safe_external`. Patch corrige les deux chemins.
- **A09-NEW-01** : scrubber ne couvrait QUE `server.log`. Refacto en module `log_scrub.py` + `install_scrub_on_root()` qui auto-patch les futurs handlers.

Nouvelles trouvailles :
- **A01-NEW-01** `/update_security_exec` sans `@require_role` -> falsification conformite CVE
- **A01-NEW-04** SSE log streams sans `@require_role(2)` -> info disclosure
- **A02-NEW-01** bcrypt cost 10 par defaut PHP -> bump a 12 (OWASP 2024)
- **A02-NEW-02** `change_password.php` n'appliquait PAS `passwordPolicyValidateAll()` -> bypass complet
- **A04-INSEC-N1** cron `* * * * *` accepte -> clamp 10 min minimum
- **A04-INSEC-N2** rate-limit CVE scan **60s par user**
- **A04-INSEC-N4** step-up auth (re-2FA) sur actions destructrices + modal UI automatique
- **A04-INSEC-N5** kill-switch `/revoke_service_account` (superadmin) -> userdel + sudoers purge en masse
- **A05-NEW-01/02/03** Docker hardening dans `prod.yml` : `cap_drop ALL`, `read_only`, `tmpfs`, user 1000
- **A05-NEW-04** CSP nonces (CSP3 ignore unsafe-inline si nonce present)
- **A07-NEW-01** rate-limit 2FA **par IP** (migration 046)
- **A08-NEW-01** `maj.sh` `git verify-commit HEAD` (permissif par defaut, strict via `MAJ_REQUIRE_SIGNED=1`)
- **A10-SSRF-N2** webhook URL guard + plus de log de `resp.text`
- **A10-SSRF-N4** `connect_ssh()` Python blocklist host (defense-in-depth meme si PHP contourne)
- **CMD-INJ-02** `shlex.quote` sur `home`/`uname`/`backup_path` dans `bashrc.py restore`
